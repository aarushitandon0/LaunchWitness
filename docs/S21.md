## Decisions (unattended)

1. **Order lines keep `option_label` / `choice` only when the item has them** (older readers of `items_json` see the same
   three keys for plain items). Every reader uses `.get()` / `items.line_label`.
2. **A `qty_<i>` box for an item that now has options, or an option index that doesn't exist, is refused** with a plain
   message when it carries a quantity; a stale box with 0 is ignored. A box for an item index that no longer exists is
   still ignored, as before S21.
3. **Min / max count all of an item's options together**; the one choice applies to the whole item (all its sizes).
4. **Item notice** applies only when it is longer than the shop's `min_notice_days`; an order with such an item needs a
   date ("X needs 7 days' notice. Please pick the date…"). The date box appears when any orderable item has such notice.
5. **`unit` wording is fixed** ("per piece", "per kg", "per gram"…): "₹40 per rose" would need free text, so a rose is
   "per piece". `option_kind` "" reads "Options".
6. **Sold out with every item**: the page has no quantity box, so `proof.find_order_form` now returns the order form even
   without boxes; the checker still demands the boxes its own test order uses whenever any item can be ordered.
7. **Grouping is conservative**: same base name AND category, ≥ 2 members, no extras, no "from" prices, same food mark,
   distinct labels. On the gallery it merges only Meera's truffle cake (bakery) and the messy-WhatsApp mango achaar.
   It runs on Reader replies and demos, never on an owner's saved menu (live shops don't change until re-read).
8. **Page budget**: a small shop's raw HTML budget went 75 → 85 KB (the option rows' CSS and script, +1.4 KB gzipped) and
   a gzipped budget was added (≤ 20 KB small shop, ≤ 22 KB big menu), which is what travels (`test_s14_themes`).
9. **The strip drifts by moving the row's scroll position** (composited scroll, no layout/paint of the cards), not a CSS
   transform, so swipe / scroll-snap / arrows / Tab all work on the same element; snap is switched off only while drifting.
   The looping copy is `aria-hidden` and not focusable; reduced motion renders no copy and never moves.
10. **Demo pages also drop the sample's Instagram handle and pasted customer messages** (`demo.demo_shop`), and new demos
    get explicit motifs so all eight differ; the three older demos look exactly as before.
11. **Share text** is "Order from <shop>: <url>" (wa.me with no number: she picks the chat). The poster uses the theme's
    AA-tested accent pair.
12. Not built: a "choice" per option (one choice per item only), images per option, inventory counts (out of scope).

## Open item for the laptop: the Reader's output budget

The strict schema asks for every key, so each item now carries 8 more keys (about 35 output tokens with empty values).
`CLAUDE_MAX_TOKENS` is 1500: Meera's reply is about 1,250 tokens of JSON, so a menu of roughly 15+ items may now hit the
cap (`stop_reason=max_tokens` → the Reader retries once, then says "couldn't read"). **Not changed here** (budget rule:
the owner decides). The re-capture prints `out=` per call: if it is near 1500, set `CLAUDE_MAX_TOKENS=2500` on the VPS
(worst case +$0.015 per reading on the strong model), or make the S21 keys optional in the schema.
